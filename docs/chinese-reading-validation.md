# PaperMind 中文文献精读验收方案

> 目标：先去掉英语障碍，验证 PaperMind 是否真的能帮助用户读懂、判断和沉淀一篇论文。
> 本轮不是测试“AI 会不会总结”，而是测试完整精读闭环。

## 一、测试材料怎么选

第一轮只选 **1 篇与你当前研究高度相关、正文文字可以复制的中文 PDF**。优先选择结构完整的原始研究，暂不选扫描件、图片型 PDF、指南或超长学位论文。

第一篇跑通后，再补两篇不同设计的中文论文：

1. 一篇观察性或预测模型研究，用于测试变量、统计方法和结果解释。
2. 一篇干预研究或随机对照试验，用于测试干预、对照、结局和偏倚判断。
3. 一篇综述或质性研究，用于测试不同论文结构下的适应能力。

扫描件应单独作为 OCR 能力测试，不能和精读能力混在第一轮一起判断。

## 二、固定测试流程

每篇文章都按同一顺序操作，不临时改变任务：

1. 上传 PDF，确认题名、作者、摘要和正文能正常显示。
2. 运行“精读路线图”，看它是否指出真正值得优先阅读的部分。
3. 运行“摘要带读”，核对研究问题、对象、设计、变量和主要结果。
4. 分别在方法、结果、讨论页运行一次“当前页陪读”。
5. 划选一个方法段落和一个结果段落，分别执行“精读这段”。
6. 至少保存一张方法卡、一张发现卡、一张批判卡和一张迁移卡。
7. 对一个你本来就知道答案的问题追问，检查回答是否忠于原文。
8. 导出或查看最终笔记，判断它能否支持组会汇报、选题或后续写作。

## 三、验收评分

每项记为 `通过 / 部分通过 / 不通过`，并保留一个具体例子。

| 验收项 | 通过标准 |
|---|---|
| PDF 可读 | 文字层可选择，页码和原文位置基本准确 |
| 研究问题 | 能说清对象、核心问题和研究设计，不只复述标题 |
| 方法理解 | 能识别样本、变量/干预、结局和关键分析方法 |
| 数字忠实 | 不改错样本量、效应方向、统计量、区间和显著性 |
| 证据边界 | 能区分“论文发现了什么”和“论文不能证明什么” |
| 当前页陪读 | 能说明本页在全文中的作用，而不是只做段落摘要 |
| 原文回溯 | 卡片、笔记或回答能回到对应页码和原文 |
| 迁移价值 | 至少产生一条对你研究设计、分析或写作真正有用的启发 |

出现以下任一情况，本篇直接判定为未通过：

- 编造原文没有的方法、结果或结论。
- 把相关性说成因果关系。
- 改错关键数字、方向或人群。
- 无法回到支持回答的原文位置。
- 输出看起来完整，但读完后你仍不知道下一步该读哪里、验证什么。

第一篇建议达到：8 项中至少 6 项通过，且没有致命错误。三篇阶段建议：至少 2 篇达到同一标准，才进入英文增强阶段。

## 四、怎么记录问题

每个问题只归到一个主类别，避免笼统写“AI 不够聪明”：

| 类别 | 典型问题 |
|---|---|
| PDF/解析 | 无文字层、乱码、页码错、选区漂移 |
| 事实忠实 | 数字错误、遗漏限定条件、编造结论 |
| 方法理解 | 不认识研究设计、变量关系或统计方法 |
| 带读策略 | 只做摘要，不告诉用户该看哪里、确认什么 |
| 沉淀闭环 | 卡片重复、不能回原文、笔记无法复用 |
| 语言辅助 | 英文术语、长句、翻译不准确；中文阶段暂不评此项 |

## 五、进入英文阶段后增加什么

中文闭环通过后，英文阶段保留完全相同的验收流程，只额外增加四项语言辅助：

1. 术语在本文语境中的含义，而不是词典释义。
2. 关键长句的逻辑拆解，而不是整页机械翻译。
3. 数字、变量名、量表名和方法名在翻译中保持一致。
4. 原文与中文解释并列，用户随时能回到英文证据。

因此英文能力不是另做一套产品，而是在已经成立的精读闭环上增加一层语言支架。
